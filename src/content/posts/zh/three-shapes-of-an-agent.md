刚开始在公司做 Agent 的时候，我对这个词的理解很简单：调一次模型，看它的回答，决定下一步，再调一次。过去一年里，同一类系统我用三种方式做了三遍：第一次直接围着 Bedrock 的 API 写循环，第二次迁到 Bedrock AgentCore，第三次做成了 Claude Code 插件。每换一次，"Agent" 这个词的含义都变了一点，我自己要写的东西也少了一截。

这篇文章讲一下这三种做法分别是什么样，各自适合什么场景，最后说说我现在怎么选。

## 形态一：围着模型 API 写一个循环

第一套系统是一组放在 Slack 里的助手，每个负责一类任务：读文档、写方案、改代码。表面上是几个不同的机器人，底层其实是同一个东西：通过 Bedrock API 对 Claude 发起一次无状态调用，外面包一层我们自己写的代码。

无状态这个词很重要。模型两次调用之间什么都不记得，不会自己去调工具，也不知道什么时候该停。所以模型不管的事，都得代码来做：

- 把对话存下来，下一轮才知道上一轮说了什么
- 解析模型的回答，判断它想调哪个工具
- 队列和重试，因为工具会失败，模型会超时
- 一个"是不是做完了"的判断，用来跳出循环

半年之后，仓库里大部分代码都是这一层。助手真正干活的逻辑反而很薄。系统能用，大家每天也在用，但每加一个新功能都要经过这层自己写的 runtime。而这个 runtime，当初谁都没打算专门去写。

## 形态二：交给托管的 runtime

第二版把循环从我们的代码里拿掉了，迁到 Bedrock AgentCore 上。之前手写的那些部分，会话、记忆、工具调用、身份、重启后能接着跑的长任务，都由 AgentCore 负责。我们带过去的只有三样：指令，工具定义，以及几条"什么时候应该停下来问人"的规则。

收益在 diff 里一眼就能看出来，runtime 目录基本清空了。

让我有点意外的是，精力并没有省下来，只是换了地方。循环没得调了，整个系统的质量就取决于两件事：指令写得清楚不清楚，工具契约是不是可靠。举个例子，有个工具说它"返回工单详情"，但偶尔会返回一个只有 key 的空对象。以前这算管道层的 bug，改一下解析就好；现在它变成了 Agent 的判断错误，因为 Agent 会拿着那个空对象接着推理。

代价是多了一层边界。出问题的时候，要透过 AWS 的抽象去排查，状态也存在 AWS 那边。如果循环本身不是你产品最核心的部分，这个交换是值得的。对我们来说确实不是。

## 形态三：一个插件里的几个文本文件

第三种是我之前没想到的。

一个帮工程师写测试的 Agent，没有部署成服务，而是做成了 Claude Code 插件，直接跑在开发者已经打开的编码助手里。没有服务器，没有队列。整个 Agent 就是一个文件夹：几个 markdown 文件写指令，一份它可以调用的 MCP 工具清单，再加一两个脚本。runtime 是用户笔记本上的 Claude Code，凭据用的是用户自己的。

这样一来，"部署"的含义就变了。发新版本就是在插件 marketplace 里升一个版本号。权限不需要单独申请，用户有什么权限，它就有什么权限。而且因为人就在旁边，Agent 每次要往共享系统里写东西之前，都可以先停下来问一句"这样改可以吗"。对于共享系统来说，这正是你想要的行为。

它做不到的事情也很明确：不会在夜里自动跑，不会自己去领工单。它的自主程度和一场对话差不多，也就是说没有。

## 三种形态对比

| | 自己写循环 | 托管 runtime | 插件 |
|---|---|---|---|
| 例子 | Bedrock API + 自己的代码 | Bedrock AgentCore | Claude Code 插件 |
| 循环由谁跑 | 你的代码 | runtime | 用户本地的助手 |
| 状态存在哪 | 你的数据库 | runtime 的存储 | 对话本身 |
| 你要写什么 | 代码 | 指令 + 工具契约 | 指令 + 工具契约 + 几个脚本 |
| 怎么发布 | 部署一个服务 | 更新指令 | 升版本号 |
| 用谁的凭据 | 服务账号 | 服务账号或 runtime 的身份 | 用户本人 |
| 能不能无人值守 | 能，但要自己实现 | 能 | 不能 |
| 人能不能逐步确认 | 要自己实现 | runtime 支持暂停才行 | 默认就是这样 |
| 适合 | 一次性的转换，没有需要保存的状态 | 在共享频道里自主运行的任务 | 每一步都需要人来决定的工作 |

## 三次都没变的东西

把三种形态放在一起看，最明显的一点是：我自己写的部分一次比一次少，也一次比一次更像文字而不是代码。从代码，到配置，到指令。指令和工具契约这两样东西，比任何一个循环都活得久。从 Bedrock 到 AgentCore 再到 Claude Code，它们几乎原样迁移过去，因为一直都是纯文本。

<div class="callout">
<p><strong>我现在的选法：</strong>先把 Agent 写成文本，最后再决定用什么 runtime。</p>
<ul>
<li>没人盯着也要跑、发生在共享频道里的任务：用托管 runtime。</li>
<li>每一步都应该由人来决定的工作：把 Agent 放到这个人已经在工作的地方。</li>
<li>一次性的转换、没有值得记住的状态：直接写循环就够了。</li>
</ul>
</div>
