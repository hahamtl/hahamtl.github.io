第一份软件工作里我做的第一样东西不是测试，是一个生成测试数据的脚本，因为手写数据比跑测试花的时间还长。第二样是一个小工具，让别人不用来问我也能跑那个脚本。这两样我都没当成"我的工作"。我的工作是测试。

十二年后，我的头衔换了四次，大部分时间在做给工程团队用的 AI Agent：规划工作、写测试、开 PR。回头看，我从第一周起就在做同一件事，这一点我看了很久才看出来。

## 四个阶段，一条线

**自动化框架。** 摩擦是重复：同样的检查，每次发版手动跑一遍。做的是一个别人不用懂内部就能往里加东西的框架。学到的是：没有第二个人提交的框架，只是我的脚本换了个长名字。

**内部工具和共享服务。** 摩擦换了位置：不是跑测试，是要拿到数据、环境和权限才能跑。做的是带真正 API 和小 UI 的服务，当产品来维护，有 roadmap。学到的是：内部工具最难的从来不是代码，是让第二个团队依赖它。

**平台。** 摩擦又换了，换到系统之间的接缝上：测试管理、工单、CI、被测服务。做的是一层跟它们全都能对接的东西，让人不用一个个去对接；后来是一个 tool server，让 AI 助手也能对接它们。学到的是：好的接口比它背后的每一个系统活得久。

**AI Agent。** 现在的摩擦是速度：开发比周围的人快了。做的是一个先把规划、测试、工单做出初稿的 Agent，每一步由人决定。正在学的是：前三个阶段的所有东西仍然是这份工作。Agent 的上限就是它能调的工具和拿到的规则，而那正是我一直在做的工具和规则。

## 变了什么，没变什么

| | 阶段一 | 阶段二 | 阶段三 | 阶段四 |
|---|---|---|---|---|
| 摩擦 | 重复 | 拿不到 | 接缝 | 速度 |
| 做的 | 框架 | 服务 | 一层 + tool server | Agent |
| 谁在用 | 我的团队 | 几个团队 | 所有团队，一个接口 | 开着助手的任何人 |
| 成功的标准 | 有人提交了 | 有人依赖了 | 有人接进来了 | 有人批准了草稿并留下了 |
| 没变的 | 摩擦都在人和系统之间 | | | |

最后一行就是这整篇。从左到右读，列的边界就模糊了。

## 为什么要写下来

因为头衔两头都误导人。"测试自动化开发"低估了第一年这份工作已经是什么；"AI 赋能"高估了第十二年这份工作有多新。如果你在类似的路上走得还早，担心地面一直在动：它确实在动，而且不要紧。能积累的不是框架、服务或模型，是看着一群人和一堆系统，能看出哪里在摩擦。

<p><strong>规则：</strong>头衔变的时候，写下你之前在去掉什么摩擦、现在在去掉什么摩擦。两句话一样，你就没换工作，只是把手上这份做得更好了。</p>
