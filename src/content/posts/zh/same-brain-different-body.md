相隔一周，来了两个要同一件事的请求。

一个来自终端前的工程师："帮这个 ticket 规划测试。"他想看到方案，跟它讨论，然后批准。另一个来自晚上六点聊天 thread 里的经理："明早之前把测试规划好。"没有人会盯着。

同一个技能。同样的指令、同样的工具调用、同样的输出格式。我以为唯一的区别是触发方式。这个假设让我花了两个月，处理了一堆零零碎碎、看起来互不相关的 bug，才看出规律。

## 身体一换，三件事跟着变

脑子是技能本身：一份 markdown 文件，写着读什么、决定什么、产出什么。它在不同 runtime 之间几乎可以原样迁移，这个我之前写过。身体是它周围的一切，而身体从实时对话换成无人值守的运行时，有三件事完全不同。

**谁在看。** 终端里，人逐行读它的输出。定时任务里，没人看，最早也要等到早上。

**什么时候可以问。** 对话里，问一句很便宜。凌晨三点的任务里，问一句等于这一轮白跑。

**什么叫做完。** 终端里，人说完就完。无人值守，"完"必须是系统自己能验证的状态。

## 交互式这边出的问题

这边的 bug 都来自一个错误：把对话当成批处理。

**问题一个一个地问。** 一个评审 Agent 问一个追问，等，再问一个，再等，再问第三个。每个问题单看都合理，合起来是最差的对话体验。现在的规则很直接：把剩下的问题全部合成一轮，已经回答过的不重复问。

**状态和实际不一致。** 有人报告一个编码 Agent "卡"了一个半小时。实际工作 94 秒就做完了，最后那条消息太长，聊天平台发送失败，屏幕上留下一个"仍在运行…"的占位符。另一处，机器人显示"尚未开始，请批准"，而任务其实已经跑了四分钟，用户照着提示再批准一次，同一个昂贵任务付了两次钱。在对话里，状态消息就是产品本身。它一旦有可能和现实不一致，就一定会在最糟的时刻不一致。

**默默地猜。** 一个 thread 里提到两个工单，Agent 选了一个，什么都没说。第一版修法是让模型更聪明地选，被直接否了。第二版是停下来追问，结果把 thread 锁死了，因为对话历史从不重置，一条很早的提及能把整个 thread 永久卡住。最后站住的是最简单的修法：保留原来的规则，但每次把选择说出来。在实时界面上，"说清楚"比"防止"有效的次数比想象的多。

## 无人值守这边出的问题

这边的 bug 来自反过来的错误：把无人值守的运行当成对话。

**它从来没开始新对话。** 一个夜间 Agent 每晚汇报"这是第四次因为同一原因失败"。我们清了它的记忆，第二天晚上它又说了一遍。原因是传给 runtime 的一个标识符在每次运行之间从来没变过。Agent 根本没在"记忆"任何东西，它一直在一周前的那场对话里。在聊天里，长对话是特性；在任务里，每次运行必须干净开始，需要持久化的身份要用另一个专门的 key。

**它等一个不在的人。** "可以继续吗？"这种 gate 在有人在场时是正确设计。无人值守时，同一个 gate 就是一个挂到早上的任务。无人值守的身体不能提问，所以需要另一种安全网：只写草稿，不确认，让人早上来审。这是上一篇的一句话版。

**它安静地失败。** 一个工具返回零条结果，Agent 用通用知识作答，很自信，也是错的。在对话里会有人说"我问的不是这个"。夜里，错误答案直接进了报告。无人值守的 Agent 需要"失败要响"的默认设置：空结果算错误，缺输入就停止运行，失败发到人第一眼会看到的地方。

## 并排比较

| | 交互式身体 | 无人值守身体 |
|---|---|---|
| 谁在看 | 人，实时 | 没人，要等 |
| 提问 | 允许，合成一轮 | 不允许；缺输入直接停 |
| 安全网 | 每次写入前一个 gate | 草稿，Agent 不确认 |
| 会话 | 一场长对话就是重点 | 每次运行全新；持久身份是单独的 key |
| 状态 | 不能和现实不一致；每个选择说出来 | 结果和每个失败发到人会看的地方 |
| 工具返回空 | 问，或者说明 | 当作错误 |
| 做完 | 人说完才完 | 系统可验证的状态 |
| 合适的 runtime | 用户笔记本上的助手 | 托管 runtime 或调度器 |

## 先选哪副身体

拿到一个新技能，我用一个问题选身体：这件事是不是每一步都应该由人决定？是，就做交互式身体，把技能放到那个人已经在工作的地方。如果价值正好在于"没人在的时候它也在跑"，就做无人值守身体，并接受它不能提问。

然后为这副身体写运行规则。不是从另一副身体复制过来。脑子是共享的，身体不是。

<div class="callout">
<p><strong>规则：</strong>技能可以迁移，运行规则不能。把技能挪到新界面之前，把提问、状态、会话、失败这四条规则按新界面重写一遍，然后在没人盯着的情况下跑一次试试。</p>
